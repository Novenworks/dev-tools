# Interaction principles

Start each screen with the task a person wants to do. Use Git terminology alongside detailed repository states and troubleshooting. Keep the primary actions in stable positions even when setup is incomplete.

Before a write, explain the affected folder, local settings or service, what data can change and where to review the outcome. Prefer one confirmation at the point where a plan becomes an action. For reads, go straight to the results and disclose any optional fetch or report write separately.

Use keyboard focus text as well as color. Offer arrow keys and Enter when the host supports direct key input. Keep numeric or letter selection and a typed Back option. Keep project search available by partial name. Test empty states, retries and return navigation with keyboard only.

A summary should report observed outcomes, skipped items and a practical next step. Home counts local project folders and labels health as a local snapshot. Distinguish a successful process launch from an editor window that the CLI cannot observe.
